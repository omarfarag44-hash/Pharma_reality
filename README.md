# PHARMA REALITY — Sprint 1

**An AI-ready pharmacy retail management simulation.** You play the **Area Supervisor** of the Central Region of **NEXUS PHARMACIES**, a fictional Saudi community-pharmacy chain: 15 branches, 60 pharmacists (15 Branch Leaders), 3 peer Area Supervisors, 8 central departments and an executive team.

Sprint 1 delivers the **organisational foundation**: the world, its data model, the analytics engine and the screens to explore it. No AI simulation runs yet — the architecture is prepared for it (see [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md)).

> NEXUS PHARMACIES is entirely fictional. All people, branches and figures are synthetic and generated deterministically. It does not represent the structure or data of any real company.

Arabic (RTL) is the default; the language switch keeps the current page and filters.

## Quick start (demo mode — no credentials needed)

Requirements: Node.js 20.9+ (22 recommended).

```bash
npm install
npm run dev          # http://localhost:3000 → redirects to /ar
```

The header shows a **Demo mode** badge. Demo data is generated by `src/data/seed/generator.ts` and is identical on every run.

## Scripts

| Command | What it does |

| `npm run dev` / `build` / `start` | Next.js development, production build, production server |

| `npm run screenshots` | Captures screenshots of a running app into `docs/screenshots` |

## Connecting Supabase

1. Create a Supabase project.
2. Apply the schema and seed — either with the Supabase CLI:
   ```bash
   supabase link --project-ref <ref>
   supabase db push                       # applies supabase/migrations/*
   psql "$SUPABASE_DB_URL" -f supabase/seed.sql
   ```
   or by pasting the three migration files, then `supabase/seed.sql`, into the SQL editor (in that order).
3. Create a user in **Authentication → Users**, then link it to the Area Supervisor character:
   ```sql
   select public.link_auth_user('you@example.com');
   ```
4. Set `NEXT_PUBLIC_SUPABASE_URL` and `NEXT_PUBLIC_SUPABASE_ANON_KEY` in `.env.local` and restart. The app now requires sign-in (`/{locale}/login`) and reads through Row Level Security.

Only the **anon** key is used by the app. The service-role key is never needed by, or exposed to, the web application.

## Self-hosted PostgreSQL (optional)

Set `DATABASE_URL` (server-only). Apply `supabase/migrations/*` and `supabase/seed.sql`. On plain PostgreSQL, first run `scripts/db/supabase-shim.sql` (creates the `auth` schema and roles Supabase normally provides). This mode has no sign-in; keep it private.

## Deployment (Vercel + Supabase)

1. Push the repository to GitHub and import it in Vercel (framework: Next.js; defaults are fine).
2. Add the environment variables from `.env.example` (only `NEXT_PUBLIC_SUPABASE_URL` and `NEXT_PUBLIC_SUPABASE_ANON_KEY` for Supabase mode; none for a public demo).
3. Deploy. `/api/health` reports the active mode and the organisation counts.

Any Node.js host works too: `npm ci && npm run build && npm run start`.

## Project layout

```
src/
  app/[locale]/…        Next.js App Router pages (server components)
  components/ui         shadcn/ui components (Radix + Tailwind)
  components/…          layout, charts (Recharts), org chart, directory filters, shared
  domain/               Domain models & bilingual catalogues (no framework code)
  data/seed/            Deterministic world definition + generator + SQL renderer
  data/sources/         Demo, Supabase and PostgreSQL loaders + row mapping
  data/repository/      OrgRepository interface + implementation (one API for every source)
  services/             View models (dashboard, branches, people, org chart, regions)
  lib/analytics/        Business calculations (pure, unit-tested)
  lib/simulation/       90-day calendar
  lib/i18n/             Arabic/English dictionaries and formatting
  validation/           Zod schemas (URL filters, dataset integrity)
supabase/migrations/    Schema, simulation foundation, RLS
supabase/seed.sql       Generated seed (checked by a unit test to stay in sync)
tests/unit|integration|e2e
docs/                   Architecture, test results, sprint report, screenshots
```
